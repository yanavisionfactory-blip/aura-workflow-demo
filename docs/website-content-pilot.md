# Five-page website content pilot

The authenticated AURA runtime accepts `AURA_WEBSITE_CONTENT_V1` followed by
the JSON in `examples/website-content/request.json`. This is a real workflow,
not result playback or a prewritten report. Its source steps perform bounded
public HTTPS GETs for the agency reference, sitemap, CMS discovery and five
existing pages. The content step calls the configured model and validates the
five complete page drafts, observed CTA destinations, asset candidates and
source receipts. The input contains URLs and scope, not authored page copy.

Kastner Hill Learning is selected from Lion’s Share Digital’s public portfolio.
The WordPress REST namespace on its own origin establishes public CMS evidence;
it does not establish authenticated client access or draft-creation permission.
Shopify, WooCommerce and BigCommerce are alternatives, not required accounts.

When one connected account exposes `google-drive.search-files` or native
`drive.files.search`, the recipe also executes a scoped client-name metadata
search. An empty result remains an empty result; it is not proof that the
client has no files elsewhere or that Drive is the client's asset system.
No unrelated file bodies are opened. Ambiguous account choices are not guessed.

The final primary result is the native website-content component, reopened from
the saved run receipt. It exposes five full page drafts, comparisons, pending
approvals, developer handoff, source timestamps/hashes and per-tool results.
The AURA content tool opens the actual copy, rather than an intake report or
transport JSON. A structured JSON export contains every page field and its
version, candidate assets, provenance and staging conditions.

No approved private brand brief or asset manifest has been supplied for this
pilot. The working brief is explicitly derived from the current public site;
public images remain candidates with unverified rights and approvals. All five
content approvals remain pending, with no invented reviewers or approval dates.
The selected client's asset-storage, approval and project-management systems
are confirmed separately from CMS evidence, and remain unconfirmed until actual
evidence is provided. AURA holds the pilot tracker and handoff only.

All source actions are GET-only, public endpoints and redirects are validated,
response size and redirect count are bounded, and signed source receipts prevent
the model step from accepting altered source data as a completed network read.
The model does not receive credentials and cannot call external tools.

This route makes no CMS writes, external document or task creation, messages,
publishing or scheduling. After exact content and asset approval, verify the
selected client's account/domain and create-page draft capability. If supported,
stage separate unpublished records, retain their IDs by page/version, and read
back content/status/metadata; never update published IDs or shared live assets.
If unsupported, use the structured export. The pilot itself stops at review.

Validation includes source parsing, actual recipe compilation, broker account
selection, connection-topic handling, source tamper rejection, redirect safety,
model invocation, draft completeness, pending approvals, primary-result routing
and rendering of every page/tool/result view. Mocked tests do not establish
live execution; inspect the saved production run for that evidence.
