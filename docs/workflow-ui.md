# Workflow preview and results

These rules apply to every AURA workflow, including newly connected tools.

## Preview

- Lead with an app screen showing the exact prepared content: a spreadsheet grid,
  document, conversation, message, task or other recognizable workspace.
- Use the shared `ToolActionScreen` when a dedicated editor is unavailable.
  A raw schema form must never be the default preview.
- Label these screens as draft previews. They are representations of prepared
  data, not screenshots of changes already saved in the external app.
- Keep model parameters, IDs and other configuration under **Action settings**.
- Edit meaningful content in the screen where possible. Apply edits to the same
  arguments that are validated and submitted for approval. Preserve read-only fields.
- Show unresolved content as pending preparation. Do not invent completed output,
  competitors' metrics, illustrative values or successful writes.

## Results

- Start with a concise outcome and only metrics supported by saved receipts.
- Follow with compact **What happened** rows and **Tools used**.
- Show the final output in its tool screen, expanded by default. Preserve its real
  content, destination link and available tool view.
- Put raw responses, operation names and diagnostics behind activity/details.
- Preserve the distinction between failed, pending, empty and completed results.
- If a backup generator was used, keep the requested provider in the plan and
  disclose the actual generator and sanitized reason in execution and results.
  Never attribute a backup response to the requested provider.

Validate the shared preview and results at desktop and mobile widths. Horizontal
scrolling belongs inside a spreadsheet or table, never on the whole page.
